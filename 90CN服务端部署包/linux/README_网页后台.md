# 网页管理后台（dnf90admin）

把原本只能在 Windows 图形版「运维工具 / 管理工具」里做的日常运营操作，搬到浏览器里。跑在 Ubuntu 服务端同一台机器上，`install.sh` 会自动装好。

---

## 一、怎么打开

安装完成后，`install.sh` 最后会打印两行：

```
地址       : http://你的公网IP:18114
后台密码   : xxxxxxxx
```

浏览器直接打开这个地址，输入密码即可。手机浏览器也能用。

**如果打不开，按顺序检查：**

1. 云服务器**安全组**放行 `TCP 18114`（和游戏端口一样在控制台配）；
2. 服务器上执行 `systemctl status dnf90admin`，确认 `active (running)`；
3. 查看后台日志：`journalctl -u dnf90admin -n 50 --no-pager`。

### 更安全的访问方式（推荐）

后台默认是 **HTTP 明文**，密码会以明文经过网络。如果在意安全，有两种做法：

**方案 A：只允许自己的 IP 访问**  
云服务器安全组的 `18114` 规则，来源填你家的公网 IP（而不是 `0.0.0.0/0`）。

**方案 B：完全不对公网开放，走 SSH 隧道**

1. 编辑 `/root/linux/conf/dnf90.env`，把 `OPEN_ADMIN_FIREWALL=false`；
2. 重新执行 `sudo bash install.sh`；
3. 在你自己电脑上执行（Windows 用自带的 PowerShell/CMD 也行）：
   ```
   ssh -L 18114:127.0.0.1:18114 root@你的公网IP
   ```
4. 然后浏览器访问 `http://127.0.0.1:18114`。

## 二、能做什么

### 1. 概览

游戏服务端是否在线、在线角色数、频道数、等级上限、数据库是否就绪、生效/历史封禁数。

### 2. 角色管理（等级 / SP·TP / 转职 / 黑钻 / 副本权限 / 装备槽）

填**完整账号**或**角色名**查询（自动识别），列表里点「选择」后出现操作面板：

| 功能            | 说明                                                                    |
| ------------- | --------------------------------------------------------------------- |
| **黑钻开通 / 续期** | 黑钻是**账号级**权益（整个账号共享）。天数默认 30，范围 1~3650；续期在原到期时间上**叠加**。可查当前剩余天数与到期时间。 |
| **等级**        | 设置目标等级；**只能升不能降**（服务端限制）。                                             |
| **SP / TP**   | 设置**剩余**点数（0~65535）；勾选「同时提升上限」可在超出时提升总上限。                             |
| **转职**        | 职业 job（0-15）、一次转职（0-15）、二次转职（0-2）。                                    |
| **副本权限**      | 一键按**每个副本的最高难度**解锁全部副本（约 880 条，数据来自内嵌难度表）。                            |
| **特殊装备槽**     | 一键解锁全部装备槽位。                                                           |

> 所有修改都走服务端**原生仓储事务**；角色在线时会立即下发原生刷新包（客户端马上生效），离线则明确提示「下次登录生效」。

### 3. 物品与邮件（搜索物品 + 发放装备）

**左栏：搜索物品** — 目录由服务端从 `Script.pvf` 解析，可按名称或 ID 搜，支持按类型（装备/材料）、稀有度、最低等级筛选，带分页。点「详情」看物品说明与属性。

**右栏：发送邮件 / 发放物品**

- 收件角色填账号或角色名（自动消歧）
- 可填标题、正文、附带**金币**
- 从搜索结果点「发放」把物品加入待发列表，**最多 10 件**（服务端限制）
- 每件物品可单独设置：
  - **数量**
  - **是否绑定**
  - **普通装备**可设 **0-31 强化等级** 或 **增幅（力量/智力/体力/精神 + 0-31 增幅等级）**（服务端规定强化与增幅互斥）
- 发送后服务端**按 PVF 类型自动归位容器**（普通装备→背包、时装→时装栏、宠物/宠物装备/宠物消耗品→对应栏位），在线角色立即收到未读提示与邮箱刷新包。

### 4. 点券发放

| 项目 | 说明                               |
| -- | -------------------------------- |
| 目标 | 填**角色名**最稳妥；只填账号则自动取该账号第一个角色     |
| 币种 | 点券 / 代币券 / 欢乐代币券 / 金币            |
| 方式 | **加量**（在原余额上增加）/ **设为**（覆盖原值，慎用） |
| 数量 | 正整数                              |

发放后界面会显示 `原值 → 新值`，并带一个「查询该角色余额」按钮可供核对。

> 底层调用游戏服务端的 `/local/dnf-gm/wallet/update`，与图形版运维工具走的是同一条链路，所以语义完全一致（角色在线也能发）。

### 5. 封禁 / 解封

| 项目    | 说明                                                        |
| ----- | --------------------------------------------------------- |
| 封禁类型  | **用户名**（推荐，自动解析成账号主键）/ 账号主键 `dnf:...` / IP / 机器码 `hw:...` |
| 天数    | `0` = **永久**封禁；大于 0 表示封禁天数                                |
| 同时踢下线 | 勾选后立即断开该账号的在线游戏连接，并写一条 GM 踢人事件（登录器会关掉玩家本地客户端）             |

下方「封禁列表」会列出全部记录（含已解封/已过期），生效中的记录可以直接点**解封**或**踢下线**。

> 解封账号时会**连带解除**该账号名下的 IP / 机器码封禁（与图形版「一键三封 / 一键解封」对称）。

### 6. 通关记录

支持按记录类型查询：**副本（通关）、团本、点券消费、对话、拍卖行、金币寄售、场景**。  
可按角色名、账号、关键字过滤，可指定起止时间（`2026-10-01` 或 `2026-10-01 00:00:00` 都行），最多返回 2000 条。

> 记录功能由服务端开关控制；若界面提示「服务端未开启记录功能」，说明服务端没启用记录落盘。

### 7. 账号查询（★ 黑钻入口在这里）

直接查 `launcher_accounts`（登录器注册表）——**这是唯一能查到玩家账号的地方**，  
留空会列出全部账号。

每行有 5 个按钮：

| 按钮     | 作用                                                                                                   |
| ------ | ---------------------------------------------------------------------------------------------------- |
| **黑钻** | **开通 / 续期黑钻**（账号级）。弹窗填天数（默认 30，1~3650，续期叠加），不需要先找角色                                                  |
| 查角色    | 跳到「角色管理」并自动查询该账号的角色                                                                                  |
| 背包     | 跳到「背包 / 仓库」并载入                                                                                       |
| 邮箱     | 跳到「邮箱」并载入                                                                                            |
| 改数值    | 覆盖账号级数值：`cera` 点券 / `cargo_gold` 货物金币 / `honor_experience` 荣誉经验 / `growth_capsule_experience` 成长胶囊经验 |

> ⚠「改数值」是**覆盖**语义（直接设成那个数），且该账号有角色在线时服务端会拒绝（409）。  
> 只是想把点券"加一点"的话，请用「点券发放」或「全服 / 批量」，那两个是**增量**。

**为什么黑钻放在账号页？** 黑钻本身是**账号级**权益（服务端存在账号元数据 `premium_expire_1000`），  
只是接口以角色为入口。放账号页更符合语义，也不用先搜到角色才能操作。  
「角色管理」页里同样保留了一份黑钻面板。

### 7.5 全服 / 批量发放（★ 运营刚需）

**扫描全服**：一次列出**所有账号与角色**（账号名、角色名、等级、点券、金币、在线状态），  
结果缓存 60 秒。

> 原理：服务端没有"列出全服角色"的接口（`GMCharacters` 只返回本机账号），  
> 所以后台按 `launcher_accounts` 全量账号 → **并发**逐个按 `account_id` 查角色的方式拼出名单。

**批量发放**：

| 范围        | 说明                   |
| --------- | -------------------- |
| 全部角色      | 全服每个角色各发一份           |
| 仅勾选的角色    | 表格里勾选后只发这些           |
| 每个账号仅首个角色 | 每个账号只发一次（防同账号多角色重复领） |

| 内容                    | 说明                                                    |
| --------------------- | ----------------------------------------------------- |
| 点券 / 代币券 / 欢乐代币券 / 金币 | 支持「加量」与「设为」                                           |
| **黑钻**                | **全服一键开通/续期**。自动按**每个账号一次**执行（防止同账号多角色把天数叠加 N 倍），天数可填 |
| 物品 / 邮件               | 用「物品与邮件」页的待发清单（含强化/增幅），可附带金币                          |

**特性**：

- 任务在**后台异步执行**，页面显示**进度条**（成功/失败计数）
- 「看失败明细」可列出每个失败角色与原因
- 点表格里的**角色名**可直接跳去对该角色单独操作；每行还有「发放 / 背包」快捷按钮
- 单次任务上限 5000 个角色（防误操作把服务端打满）
- 点券/金币发放走 `mode=add` 增量，不会覆盖玩家现有余额

### 8. 背包 / 仓库

填账号或角色名 → 载入背包快照（容器、槽位、物品 ID、名称、数量、绑定状态）。  
支持**删除单件**与**清空整个容器**（清空前二次确认）。容器包含主背包、时装、宠物、仓库等。

### 9. 邮箱

填账号或角色名 → 载入邮箱邮件列表，支持删除单封邮件。配合「物品与邮件」页可完成"发 → 查 → 删"闭环。

## 三、配置文件

`/opt/dnf90/admin/admin.json`（由 `install.sh` 生成，权限 600）：

```json
{
  "listen": ":18114",
  "password": "后台登录密码",
  "session_secret": "会话签名密钥",
  "game_admin_url": "http://127.0.0.1:18111",
  "game_admin_token": "adm_xxx",
  "mysql": { "host": "127.0.0.1", "port": 3306, "user": "dnf90", "password": "xxx", "dbname": "dnf_local" },
  "title": "DNF90 管理后台",
  "trust_proxy": false
}
```

| 字段                 | 说明                                                                                                                 |
| ------------------ | ------------------------------------------------------------------------------------------------------------------ |
| `password`         | 后台登录密码。改这里之后执行 `systemctl restart dnf90admin` 生效。                                                                  |
| `game_admin_token` | **必须**与 `/opt/dnf90/runtime/configs/dnfbridge.toml` 的 `[admin].token` 一致，否则所有游戏操作都会报「管理令牌无效」。`install.sh` 会自动保持一致。 |
| `session_secret`   | 会话签名密钥，改了所有人需要重新登录。                                                                                                |
| `mysql`            | 读封禁表用。改了密码要同步改 `/opt/dnf90/auth/config.json` 和 `runtime/configs/dnf/logic.toml`。                                   |
| `trust_proxy`      | 前面挂了 nginx 反代时设为 `true`，否则保持 `false`。                                                                              |

改完配置：`systemctl restart dnf90admin`。

## 四、安全提醒

1. **务必把 `conf/dnf90.env` 里的 `ADMIN_PASSWORD` 改成复杂密码**再重跑安装；默认自动生成的密码虽然随机，但会打印在安装日志里。
2. 后台目前是 **HTTP**。若要公网使用，建议只对自己的 IP 开放（安全组限制）或走 SSH 隧道。
3. 后台**不对外提供游戏接口**，只读写本机 MySQL 与回环 18111；即使被扫描到，没有密码也进不去（登录有失败锁定：连续 5 次错误锁定 60 秒）。

## 四点五、手动补装（不重跑 install.sh / 不重传整个包）

服务端已经正常运行、只想单独把网页后台加上去时，**只需要上传 2 个小文件**：

| 文件                     | 大小    | 说明                                                  |
| ---------------------- | ----- | --------------------------------------------------- |
| `linux/bin/dnf90admin` | ~7 MB | 后台主程序（x86_64；ARM 服务器用 `linux/bin/arm64/dnf90admin`） |
| `linux/补装-网页后台.sh`     | ~5 KB | 补装脚本                                                |

**操作步骤：**

```bash
# 1) 用 WinSCP / Xftp 把上面两个文件都上传到服务器的 /root/ 下
#    （dnf90admin 是二进制，务必用「二进制/自动」传输模式）

# 2) 执行补装脚本
cd /root
sudo bash 补装-网页后台.sh
```

脚本会自动完成：

1. 从 `/opt/dnf90/runtime/configs/dnfbridge.toml` 的 `[admin]` 段**自动读取 admin token**
2. 从 `/opt/dnf90/auth/config.json` **自动读取 MySQL 口令**（你不用手敲）
3. 校验上传的二进制是 ELF 且架构与本机一致（防止把 ARM 版传上来）
4. 安装二进制到 `/opt/dnf90/bin/dnf90admin`，生成 `/opt/dnf90/admin/admin.json`（权限 600）
5. 写入并启动 systemd 服务 `dnf90admin`，放行 ufw 端口
6. 自测本机 HTTP 是否 200，失败时自动打印日志

结束时会把**后台地址和随机生成的密码**打印出来。

**想自己指定密码**：编辑脚本第 22 行 `ADMIN_PW=""`，填入你的密码再执行。

**装完后想改密码**：编辑 `/opt/dnf90/admin/admin.json` 里的 `password`，然后  
`systemctl restart dnf90admin`。

**升级后台（已装过旧版）**：重新上传新的 `dnf90admin` 覆盖 `/root/`，再跑一次  
`sudo bash 补装-网页后台.sh` 即可。脚本会停旧服务 → 装新二进制 → 复用原有配置（密码/token 不变）  
→ 重启。**不会覆盖你改过的 `admin.json`**（脚本每次会按 `conf/dnf90.env` 重新生成，  
所以如果你手改过 `admin.json`，请把改动同步到脚本或改完再手动重启）。

**校验二进制完整性**（可选）：

| 文件                            | 大小        | SHA256                                                             |
| ----------------------------- | --------- | ------------------------------------------------------------------ |
| `bin/dnf90admin`（x86_64）      | 8,171,680 | `03f7ef0f8ce5efe9d0aa1c242b27daa6c08778ffa1ea8129d81627f5a730318a` |
| `bin/arm64/dnf90admin`（ARM64） | 7,602,336 | `e1a5213d9c8bd2f84e69b9c8e59a4802b7d4764672f681116505d43a8babb583` |

## 四点七、⚠️ 为什么"按账号查不到角色"（重要，务必读懂）

**现象**：在后台填账号名查角色，永远提示"没找到账号或角色"。

**根因**：本服有**两张不同的账号表**，很容易搞混：

| 表名                   | 谁写入                           | 内容                                            |
| -------------------- | ----------------------------- | --------------------------------------------- |
| `launcher_accounts`  | **登录器注册/认证服务**（远程模式 YH登录器走这条） | 玩家真正的登录账号 + `account_id`（`dnf:<sha256(用户名)>`） |
| `dnf_login_accounts` | 游戏服仓储自己（本地 Go 登录器走这条）         | 本地单机模式的登录账号                                   |

游戏服务端的接口 `GET /local/dnf-gm/characters?username=X` 查的是**第二张表**，  
所以拿远程登录器注册的用户名去查，**永远返回空**——不是角色不存在，是查错表了。

**正确处理链路**（网页后台已按此实现）：

```
用户名 --(后台查 launcher_accounts)--> account_id --(游戏服 GM API)--> 角色列表
```

也就是说：**"用户名→主键"这一步必须由后台自己做（查 `launcher_accounts`），  
不能交给游戏服务端**。角色数据本身在游戏服业务表里，按 `account_id` 查是通的。

> 同样的坑也适用于其他第三方 GM 工具：只要它用"用户名"去调游戏服的角色接口，  
> 就会查不到。填**账号主键 `dnf:...`** 或**角色名**通常能绕过。

**自检**：在「账号查询」页留空直接点「搜索」，会列出 `launcher_accounts` 里的全部账号。  
能看到你的账号 = 注册没问题；看不到 = 登录器还没注册成功（或注册写到了别的库）。

**卸载网页后台**（不影响游戏服务）：

```bash
sudo systemctl disable --now dnf90admin
sudo rm -f /etc/systemd/system/dnf90admin.service
sudo systemctl daemon-reload
```

## 五、想加功能？

后台是单个 Go 程序 + 一个内嵌网页，源码在：

```
90CN/DNF90运维工具/cmd/admin/
├─ main.go        入口与配置
├─ api.go         HTTP 接口（/api/*）
├─ gm.go          游戏服务端 GM API 客户端
├─ batch.go       全服批量任务队列
├─ class_names.go 职业/转职/觉醒名称表
├─ webui.go       内嵌页面
└─ web/index.html 网页界面（单文件）
```

加一个新功能通常只要三步：`api.go` 里加一个 handler → `gm.go` 里加一个 GM 调用（或复用 `store`）→ `web/index.html` 里加表单。

**重新编译**（在装有 Go 的机器上）：

```bash
cd 90CN/DNF90运维工具
GOOS=linux GOARCH=amd64 go build -trimpath -ldflags "-s -w" -o dnf90admin ./cmd/admin
```

然后把 `dnf90admin` 覆盖到服务器 `/opt/dnf90/bin/` 并 `systemctl restart dnf90admin`。
